# 본연 관제 서버

운영은 Cloudflare Worker와 기본 D1, 사진용 D1을 사용합니다. 홈페이지와 관제 정적 파일은 GitHub Pages의 `docs`에서 발행합니다. 인증·정산·메일 권한은 Worker에서 검사합니다.

## 사진 저장소

사진 DB 초기화/갱신 순서는 `server/d1-media.sql`, `server/d1-media-hardening.sql`, `server/d1-media-capacity.sql`, `server/d1-media-isolation.sql`입니다. 새 Worker보다 먼저 적용합니다. 이 SQL들은 기존 사진을 지우지 않으며 다시 실행할 수 있습니다.

즉시 촬영 사진과 기존 방식의 증빙 사진은 서버가 정한 작업자·현장 정보로 예산을 합산합니다. 운영과 검증 공간은 별도 이름을 사용합니다. 파일과 사진 조각, 예산 변경은 D1 `batch`에서 함께 커밋하거나 모두 롤백합니다.

- 작업자별 보관 예산: base64 저장량 70,000,000바이트
- 현장별 보관 예산: 140,000,000바이트
- 사진·보고 자료 전체 상한: 기존 350,000,000바이트
- 서류를 포함한 전체 상한: 기존 450,000,000바이트

이 수치는 압축 전 사진 크기가 아니라 DB에 실제 저장되는 base64 크기입니다. 카메라 화면에 서버 보관 여유가 표시됩니다. 한도에 걸린 미전송 사진은 기기에 남고, 공간을 확보한 뒤 명시적으로 재전송할 수 있습니다. 승인된 사진이나 기존 증빙을 자동 삭제하지 않습니다. 무료 저장소의 전체 용량에는 한계가 있으므로 운영자는 사용량을 확인하고 장기 보관 용량을 관리해야 합니다.

기존 파일을 전환할 때는 기본 DB의 `work_camera_photos` 및 `charger_evidence`를 기준으로 **실제 사진 DB에 존재하는 키만** `media_proof_scopes`에 `INSERT ... ON CONFLICT DO NOTHING`으로 연결합니다. 이때 원본 파일·사진 조각은 변경하지 않습니다. Worker 전환 후 다시 누락 매핑을 연결하고, 미매핑 증빙 키가 없는지 확인합니다. 사용량 카운터를 임의로 초기화하거나 매핑의 소유자를 직접 UPDATE하면 안 됩니다.

## 확인

`npm test`는 원격 DB나 실제 메일을 사용하지 않습니다. `tests/media-isolation.test.mjs`는 실제 SQLite 트리거와 저장소 어댑터를 사용해 동시 예약·롤백·기존 사진 유지·API 소유자 검증을 확인합니다. 실제 휴대폰 카메라·네트워크 차단 검증은 별도의 기기 시험입니다.

배포 전 기본 DB와 사진 DB의 스키마·행을 백업하고, 배포 후 원본 파일과 사진 조각의 해시를 대조합니다. 서비스 워커의 셸 버전도 갱신해 새 클라이언트 파일을 받도록 합니다.
